# Analytics Dashboard Studio — Comprehensive Audit (2026-08)

_Audited 2026-08-06 against `main` @ v833 / sw studio-shell-v465. Method: four
parallel deep sweeps (UI/UX + every filter mechanism, technical health,
platform-standards + fleet divergence, deploy/process), each re-verified
against the live tree. File:line references are to that commit; a few will
drift as the app moves — treat them as the starting point, not gospel._

This is an internal engineering audit, not a user-facing document. Its findings
are tracked as **AUD-01 … AUD-12** in STATUS.md NEXT (§5), mirroring how the
`FRONTEND_QA_REPORT_2026-07-24.md` QA-01…QA-10 series was worked. Every Kevin

series (see `kevinrhaas/polecat-platform` → `docs/KH-REGISTER.md`).

## 0. Executive summary

Analytics is a large, unusually capable local-first app (≈40K LOC of
first-party JS, 55 chart types, six data adapters, a dashboard builder, a View
Builder, geo/choropleth, offline PWA) built with genuine care — the changelog
discipline, the DURABLE incident fixes, the additive-migration story and the
2,928-assertion test suite are all real strengths. The debt is concentrated and
nameable, not diffuse.

**Four P1 findings** (each an `★★` workstream below):

1. **AUD-01 — Supabase save is the only non-atomic adapter** and it is the
   shipped default backend. The users-table self-destruct was fixed
   (upsert-first, tombstone-only deletes, v787/v799), but the general
   whole-snapshot model still has no cross-device conflict resolution, and a
   failed per-table read is silently adopted as an empty table.
2. **AUD-02 — Four confirmed unescaped `innerHTML` sinks** that render
   attacker-influenceable data (query-result cells, ensemble provider names,
   an imported-workspace `<option>`), and the chart sinks ship inside **every
   exported dashboard**.
3. **AUD-03 — Secrets hygiene:** the secrets-vault passphrase, the Supabase
   `authPassword`, and backend tokens all sit in `localStorage` in plaintext,
   and unsalted single-round SHA-256 password hashes sync to the remote.
4. **AUD-04 — A cluster of quiet data-loss paths:** `replaceAll()` drops tables
   it doesn't know about, `persist()` swallows quota errors with no user
   signal, and failed reads become empty truth. **This is also the hard
   precondition for analytics joining the promotion pipeline** (shared-origin
   stage previews are unsafe until a newer build's schema can't clobber an
   older client's data).

The rest is quality, consistency and hygiene — most visibly the **filter
sprawl** (§2.1) and the boot/preview **performance** cost (§1.4).

## 1. Technical health

### 1.1 Security

**Confirmed unescaped `innerHTML` sinks** (all live at audit):

| Sink | Location | Untrusted input |
|------|----------|-----------------|
| Bar-mode table cell | `app/studio-charts.js:3069` | any query-result cell value (`String(disp)`) — the non-bar branch at `:3075` correctly uses `textContent` |
| Badge table cell | `app/studio-charts.js:3072` | `b.cls` + `b.text`, derived from cell values |
| Ensemble provider chip | `app/studio-charts.js:6688` | provider `name` (and color token) straight from the dataset |
| Workspace `<option>` | `app/gate.js:410-411` (assigned `:416`) | `w.id` / `w.label` from an imported access file persisted in `studio-workspaces-custom` |

The chart sinks are the serious ones: `exporters.js` inlines `studio-charts.js`
into every exported `.html`, so each sink ships and runs against whatever data
that dashboard queries. Fixes must live in the toolkit source (not a
post-process) to preserve the **export == live-preview byte-identity
invariant**, and must not disturb the deliberate `he()`/`svgEsc` carve-out
(they run in the sandboxed export iframe where `model.js` isn't inlined).

**No Content-Security-Policy** anywhere (`app/index.html`, `index.html`,
`app/viewer.html`, `docs/index.html` — zero `http-equiv`). GitHub Pages can't
set headers, but a `<meta>` CSP would still constrain inline `eval`/injection.

**postMessage is unauthenticated.** Both directions use `targetOrigin: "*"`
(`studio.js:158`, `:9909`, `:10019`; `studio-render.js:2348`) and the receiver's
only check is a magic number `d.studio === 1` (`studio.js:10179`,
`studio-render.js:2493`) — no `e.origin`/`e.source` validation — before
dispatching full dashboard-spec mutations (`select`/`reorder`/`resize`/
`rename`/`kpi-delete`/`panel-delete`/…). The preview iframe is `srcdoc` **with
no `sandbox` attribute** (`studio.js:5303`, `:6520`, `:10427`, `:10557`;
`viewer.js:208`) — the code even says so at `studio.js:10450`. Same-origin in
the normal case, but nothing defends against a framing/handle-holding page.

`he()` at `studio-render.js:590` escapes `& < >` but **not `"` or `'`**, so any
attribute-context use is unquoted-injectable; `model.js` `svgEsc` similarly
omits `"` and truncates at 32 chars.

### 1.2 Data loss

- **Supabase non-atomic save.** The users table was hardened to upsert-first +
  tombstone-only deletes (`supabase.js` save() region ~`:465-540`, v787/v799),
  which fixed the self-destruct. But the model is still whole-snapshot with **no
  conflict resolution** — two devices editing concurrently is last-writer-wins
  over the entire workspace. And `load()` ends each per-table read chain with
  `.catch(function () {})` (`supabase.js:450`, meta `:461`), so a failed read
  leaves that table empty in the snapshot, which `replaceAll` then adopts as
  truth. (Turso batches atomically; Firebase upserts-then-prunes — Supabase, the
  default, is the outlier.)
- **`replaceAll()` drops unknown tables** (`workspace.js:124` `blank()` →
  `TABLE_NAMES.forEach` `:139-147` → `db = next` `:151`). A v5 workspace pulled
  by a v4 client and pushed back loses the v5 table. Backward-compat is
  additive; forward-compat is not.
- **`persist()` swallows quota** (`workspace.js:28-29`,
  `catch (e) { /* quota/blocked — stay in-memory */ }`) with no user signal —
  and `file` datasets inline up to 2 MB each into the same blob, so exhaustion
  is reachable; the app silently becomes memory-only until reload.

### 1.3 Secrets & auth

- Plaintext in `localStorage`: backend `key`/`token` (`analytics.datasource.v1`),
  Supabase `authEmail`+`authPassword` (`sync.js:432`, read `:148`), and **the
  secrets-vault passphrase itself** (`analytics.datasource.secret.v1`,
  `sync.js:25/30-31`). Local-first has nowhere else to keep the backend token —
  but caching the *passphrase* that's meant to protect the other secrets negates
  the vault; it should be session-only.
- Password hashing is **unsalted single-round SHA-256** (`auth.js:30-33`) and
  those hashes sync to the remote `users` table (`auth.js:173`, `schema.js:93`).
  Seeded accounts are literally `admin/admin` and `demo/demo`. Trivially
  rainbow-tableable; move to a salted, iterated KDF.
- Auth **fails open** by design at several points (no `Auth` object → app
  reveals, `gate.js:43`; `sessionStorage['studio-gate-ok']` → synthetic
  `{role:"admin"}`, `auth.js:77-83`; `!Auth||!me` → treated as admin). This is
  documented UX-gating, not security — worth restating plainly wherever real
  privacy is implied.

### 1.4 Performance

- **Boot:** 52 render-blocking `<script src>` in `app/index.html`; `app/*.js`
  totals ~2.5 MB unminified; `js/changelog.js` is ~660 KB and precached to every
  visitor; then `boot()` fetches ~20 more files as text into `S.assets`. Nothing
  renders until that resolves (a 4-second veil failsafe hides it).
- **Preview hot path:** `refreshPreview()` debounces 130 ms then rebuilds the
  entire toolkit into one HTML string and reassigns `ifr.srcdoc` — a full iframe
  teardown + re-parse of ~570 KB (up to ~4.4 MB when ZCTA geo is inlined), from
  **208 call sites**. Typing a panel title re-parses half a megabyte per
  keystroke settle. Undo is a full `JSON.stringify` of the spec per edit (cap 80).
- **Listeners:** ~185 `addEventListener` vs ~15 `removeEventListener` in
  `studio.js`; most are dropped with their nodes on `innerHTML` replace, but the
  window/document-level ones registered in re-entrant code are the exposure.

### 1.5 Code shape

- `app/studio.js` is **12,991 LOC** — it grew ~22% *net of* the nine-module R5+
  extraction. `studio-charts.js` (6,714) and `studio-render.js` (2,425) are
  never `<script>`-loaded; they're fetched as text and run only inside `srcdoc`
  iframes/exports (27% of app JS lives outside the main page). This is a
  deliberate export-invariant design, but it means two escaper families and
  duplicated helpers by necessity.
- **Dead code:** `app/gate-config.js` still ships (loaded + precached) and
  defines `window.STUDIO_GATE_SHA256` with two live access-code hashes, but has
  **zero readers** (the passcode gate it served was replaced by `PolecatAuth`);
  `DashKit.TIME_RANGE` (`vendor/dashkit.js:788`) has zero `app/` callers.
- Four HTML escapers, two real `isVisibleToMe` (studio.js + a viewer.js
  mini-fork), three PostgREST shapers (the latter two deliberate export-inlines).

### 1.6 Testing

`tests/run.js` is **40,196 LOC / 2,928 `ok()` sites** in one file under a single
top-level `try` — an uncaught throw aborts every remaining check (the Z3-WB
FATAL cascade that this hardened is the cautionary tale). ~987 `waitForTimeout`
calls sum to >3 min of unconditional sleep; a full run is ~8-15 min. Coverage
gaps: the Firebase adapter is effectively untested; there are no
concurrent-device/sync-conflict tests, no Supabase mid-save-failure test, and no
tests asserting `innerHTML` escaping or postMessage origin. The changelog
tooling (`changelog-normalize.js` network-clock + self-verify, `changelog-check.js`
verify-only) is a genuine strength worth keeping.

## 2. UI/UX consistency

### 2.1 The filter story (the headline)

The app has **19 distinct filter/search mechanisms in four families**, with
minimal shared code — the single clearest consolidation opportunity in the app:

- **A. Dashboard runtime** — the interactive filter bar (only *defaults*
  persist; live `DashKit.filterState` is never serialized, so the viewer's
  "interact then save-a-copy" captures defaults only), cross-filter (emit param
  persists, selection doesn't), drill params, the DashKit drawer row-filter
  (2000-row cap), ensemble provider toggles, and a **dead** `DashKit.TIME_RANGE`
  — meaning there is *no first-class date/range filter*; relative dates go
  through `{{today-30}}` SQL tokens instead.
- **B. Data filters** — DA output rules use **8 operators**
  (`=,!=,>,>=,<,<=,contains,startsWith`, `model.js:2956`) while the Job "Filter
  rows" step uses **7 different ones** (`eq/ne/gt/gte/lt/lte/contains`) for the
  same conceptual operation.
- **C. View Builder shelf** — `in`/`range` kinds, checkbox+search editor, a
  silent 200-value cap; fully persisted in the builder blob.
- **D. Seven catalog lists** (Home/Dashboards/Views/Datasets/Connections/Jobs/
  Repository). SORT-1 (v812) landed a genuinely shared `Studio.catalogSort` and
  bulk-move landed a shared `Studio.bulkMoveToFolder` — good, and the model for
  the rest. But the *search + facet* layers are still copy-adapted per section:
  the "Clear filters" chip exists on only some, the search haystack differs per
  section (Dashboards uniquely falls back to matching DA column names), and the
  default view mode differs (Dashboards tiles, others list).

Add the 11 other search affordances (library, inspector, chart gallery, ⌘K,
docs, folder-picker…) and the pattern is: every surface reinvented its own
filtering. **AUD-06** proposes a shared matcher/facet module and one operator
vocabulary, extending the SORT-1/bulk-move precedent to the search+facet axis.

### 2.2 Interaction consistency

- **23 bare `window.confirm` delete sites.** DURABLE-2b (v822) added
  `Studio.undoToast` to the four per-row deletes and the bulk bars, but **three
  destructive paths still have no undo**: View Builder "Delete dataset"
  (`build.js:389`), Explore saved-View delete (`explore.js:938`), and sample-pack
  removal (`studio.js:890`, which deletes datasets + Views + dashboards).
- **`viewer.js` re-implements six `studio.js` helpers** in miniature
  (`isVisibleToMe`, `currentUserIsAdmin`, engine dispatch…) and flags its own
  drift risk in a comment.
- Three export surfaces (topbar 7 formats, viewer 3, per-panel) with
  non-matching format lists; four theme-toggle surfaces with two meanings.
- Five different empty-state component families, three loading idioms — no shared
  component.

### 2.3 Discoverability & gating

- **⌘K is missing 6 of 13 sections.** `app/palette.js` offers navigation to
  Home/Dashboards/Datasets/Connections/Dashboard-Builder/Settings/Help only — no
  Views, Quick Views, View Builder, Repository, Jobs, or Admin.
- **`CONFIGURABLE_SECTIONS` omits `views`/`build`/`docs`** (`studio.js:8740`), so
  those three can never be hidden from a viewer even though the rights UI implies
  full coverage.

### 2.4 Copy truth

- Marketing states **"25+ chart types"** (`index.html:112`) and **"50+"**
  (`:205`) in the same file; the docs say **52** in four places; the real anchor
  count is **55**. Four numbers, none agreeing.
- The in-app **"What's next"** modal (`studio.js:10045`) shows six items, **five
  already shipped** (topbar actions, sample-data separation, Views language,
  PDF export, duplicate-name disambiguation) — it advertises weeks-old work as
  upcoming.
- "Studio" still surfaces in toasts/empty-states where the canonical label is
  "Dashboard Builder"; "demo" (code) vs "sample" (UI) split persists.

## 3. Standards & fleet compliance

- **Shell adoption is the least in the fleet — by written policy.** Analytics
  "migrates to the shell LAST; its conventions are canonized, not disturbed"
  (PLATFORM.md; STATUS.md's "◇ LATER — shell v2 … do NOT jump the queue"). It
  vendors v0.5.4 and routes every shell import through one chokepoint
  (`app/fleet.js`), keeping a bespoke rail, inline theming, and a token-bridge
  that *inverts* the platform model (the shell consumes app tokens). **This is a
  recorded decision, not drift** — the audit flags it only so future sweeps
  don't "fix" it.
- **Real inconsistency:** the mobile release gate is documented as **390×780**
  (`CLAUDE.md:31`) but the suite is split roughly evenly between 780 and 844
  (and the STATUS mobile-track note says 844). Pick one and make the doc match.
- **Numbering proliferation:** analytics alone runs ~20 ID schemes (LF, QA, VB,
  CONS, DURABLE, LIVE-x, Z, M [overloaded across two tracks], F, UX, E, J, K, V,
  H, G, I) plus a `#NNN` space that already means three things (PR, backlog item,
  MIGRATION row). No sibling repo has any scheme. This is the motivation for the
  fleet-wide **KH-###** series (§4).

## 4. Process & delivery

- **Deploy posture is sound and load-bearing:** tests are advisory, Guard main
  (`auto-revert.yml`) self-heals, and this exists because a hard `needs: test`
  gate once froze the live site ~21 hours. Any future gating (e.g. the promotion
  pipeline analytics will adopt as fleet rollout #2) must keep the rule
  *promotion is gated, deploy is not*.
- **STATUS.md is 14,550 lines / ~1.3 MB.** It's an excellent single source of
  truth but is now large enough that it's worth splitting the DONE section into a
  dated archive file, leaving NEXT + Conventions + a thin recent-DONE window in
  the live file. Several stale NEXT stubs (shipped EXPORT-1/DURABLE-2 duplicates
  that were never struck) should be swept in the same pass.
- **Kevin-attribution is five inconsistent mechanisms** (section headers, ~275
  inline parentheticals in a dozen formats, a `KEVIN-LIVE` badge, the LF/LIVE
  queues, and an orphaned "KEVIN-LIVE #136" with no series behind it). The
  **KH-### register** (`polecat-platform/docs/KH-REGISTER.md`, seeded from this
  audit) replaces all five with one greppable, monotonic id.
